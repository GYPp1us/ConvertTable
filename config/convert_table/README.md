# 配方配置与执行 · 1.3.1

## 编辑入口

游戏运行目录中的 `config/convert_table/recipes.json` 是服务器权威配置。首次启动世界/服务器时，从 JAR 默认值生成；后续启动不会覆盖已有配置。修改后重启世界或服务器生效。多人游戏中，客户端 UI 与查看器使用服务器同步的目录，不读取客户端自己的配方文件。

本仓库的 `config/convert_table/recipes.json` 是可直接使用的配置样例。默认内容包含原策划的 **99 个普通分组**，以及 **40 条高级策划展开成的 52 条具体配方**。三个珊瑚模板分别展开为五个同种对应关系，返还空桶。

- `groups[].enabled` / `advanced[].enabled`：关闭单个分组或配方。
- `groups[].tier`：piglin / end / sculk；高级版本继承低级分组。
- `groups[].items`：严格 1:1 组内互转，排除转换为输入本身。
- `groups[].batch`：每批上限，查看器输入输出以单件 1:1 展示并注明批量上限。
- `advanced[]`：明确的输入、催化材料、产物数量，死亡计数、是否允许自动处理、解锁文字与返还物。
- `settings.piglin`：每批金粒成本；`settings.end`：燃料、每果相位补充量、每批相位消耗。
- `settings.sculk.advanced_cost` 固定为 `death_count`，不消耗玩家经验；现阶段计数成本沿用策划数值。
- 不存在的合法物品 ID 会被排除并写入同目录 `unavailable-items.txt`。分组不足两个可用物品时不展示；高级配方任一必需物品缺失时整条不展示。原配置不删除这些条目，供未来版本使用。
- 重复 ID、负数、错误字段或过大的目录会拒绝加载并明确报错，保留文件供修正。

`execution_enabled: true` 开放实际执行和死亡收集，false 则保留目录和界面、停止所有转换与充能。已有配置不会自动覆盖：从 1.2.1 升级时须将该开关改为 true。

## 使用方式

1. 猪灵：输入材料与金粒，点击“转换一批”；组内随机不同产物，每批支付一次。输出堵塞时不扣费、不重新抽签，抽签结果随存档保存。
2. 末地：放入材料、紫颂果，选择目标。默认一果补充 16 相位，每批消耗 1；仅实际成功时补充燃料和扣费。
3. 幽匿：普通转换同末地；高级转换需要主材料、专用“催化”槽及相位/死亡计数。“返还”槽接收空桶等副产物。槽满或资源不足会完整保留输入。`auto: false` 配方仅支持投入槽中的手动按钮。
4. “连续”默认关闭，开启后每 10 tick 尝试一批，关闭 UI 仍运行。漏斗从顶部投入材料，侧面投入燃料/幽匿催化材料，底部仅取走产物与返还物。潜影盒模式原位处理盒内内容，盒子留在输入槽供手动取回。
5. “连接容器”原位修改半径内容器内容；精确匹配使用输入槽的样本，不消耗样本。同组匹配允许所有能按配方变为目标的输入。双箱计一次；上限 8 个，按坐标稳定选取；上锁容器和未开箱战利品容器不执行转换。
6. “容器内容”将潜影盒放入输入槽，直接修改盒内物品并保留盒子名称和其余内容。精确匹配锁定第一次成功转换的输入种类，切换模式/匹配方式或重新选择目标可重置。不会递归打开盒中盒。

死亡计数由服务端真实死亡事件获得：生物脚下必须是与台连通、上方无遮挡的幽匿方块顶面。默认不要求玩家击杀；不收集玩家、盔甲架或悬空死亡。共享网络按最短连通路径、X/Y/Z 坐标顺序归属一台。每只默认 1 点，上限 4096，可用 `death_count_per_mob` / `death_count_capacity` 调整。充能不拦截经验球、战利品和催发体行为。断开地面连接、卸载区块或保存不会清空已有计数；拆台会掉落物品槽内容，但台内相位和死亡储量不随台物品转移。

`unlock` 是原策划中的说明文本（例如远古城市、获得某材料），目前不接入独立玩家进度锁；实际开放条件是配方中的输入、催化材料、相位与死亡成本。查看器没有自动填充按钮。

当前检测范围仍固定为容器曼哈顿 4/8 个、幽匿曼哈顿 16/1024 节点；JSON 中相应结构与 `rules` 是策划元数据，不作为任意扫描器脚本执行。支持修改的是配方、启用开关、燃料/批次成本、死亡成本、计数容量与是否要求玩家击杀。

## 开发

`python assets/tools/export_recipe_config.py --example` 从 v1.4 TOML 重新导出默认配置和仓库样例；这不会修改测试实例内的配置。

Gradle 使用可选 compile-only API。正常构建从 Modrinth Maven 获取固定版本；离线构建可使用 `-PviewerDeps=build/viewer-deps` 指定已下载依赖。测试使用 `-PuiTest` 并搭配现有 `compatMods` 配置选择单一查看器。测试不打开用户存档。

26.3 实测有效目录为 99 个普通分组、52 条高级配方；本次测试中规划物品全部解析。
