# 转换配方配置说明

本文对应 ConvertTable **v0.3.2**；Minecraft 与 Java 运行要求以 `fabric.mod.json` 为准。

## 文件与加载

运行目录的 `config/convert_table/recipes.json` 是转换台的服务器权威配置。服务器首次启动时从模组内置默认值生成；定制配置在后续启动时保留，未改动的已识别旧默认值会备份并升级。修改后重启世界或服务器加载。联机客户端收到服务器的转换目录，不读取本机的配置文件。

仓库中的 `config/convert_table/recipes.json` 是由源数据生成的样例，不是维护默认配方的编辑入口。要维护模组随包默认值，请编辑 `规划/conversion_tables_26.3_v1.4.toml`，再运行 `python assets/tools/sync_recipes.py`；该脚本会校验源文件并重建默认 JSON、仓库样例和配方 Excel。运行 `python assets/tools/sync_recipes.py --check` 可只读核对来源、JSON、Excel 清单和文件哈希。Excel 是查看/评审产物，不是模组运行输入，也不要手工修改。

管理员可以直接编辑游戏运行目录的 `config/convert_table/recipes.json` 来定制该服务器；改完重启世界或服务器。v0.3.2 会识别完整语义等于已发布 0.1.1（原 1.5.2）、0.2.0、0.3.0 或 0.3.1 默认值的旧配置，先保留原始内容备份，再原子替换为新版默认值，补齐新增配方及费用。改动设置、禁用配方、删除条目等自定义配置均保留，不自动合并或覆盖；管理员需要自行添加希望启用的新配方。默认样例有 107 个普通分组和 118 条进阶配方。配方物品必须使用 `minecraft:oak_planks` 这样的物品 ID；规划表里的 `ID|名称` 格式不能直接放进 JSON。

`execution_enabled` 缺省为 `true`。设为 `false` 会保留配方图鉴和同步目录，但暂停所有转换及幽匿可用灵魂收集。重新设为 `true` 并重启即可恢复。

## 配方字段

`schema_version` 必须为 `1`，且根对象须包含 `settings`、`groups` 和 `advanced`。

### 普通分组

每个 `groups[]` 条目描述一个组内互转关系。例子：

```json
{
  "id": "WOOD-01",
  "name": "木板",
  "tier": "piglin",
  "batch": 64,
  "items": ["minecraft:oak_planks", "minecraft:spruce_planks"],
  "enabled": true
}
```

- `id`：必填；与所有普通及进阶配方 ID 全局唯一，只能含字母、数字、`_ . / -`。
- `name`：必填的管理标签；不参与转换判断。
- `tier`：必填，`piglin`、`end` 或 `sculk`。该档及更高级别的转换台可用此组：猪灵组供三台使用，末地组供末地和幽匿使用，幽匿组仅供幽匿使用。
- `batch`：每次普通转换最多转换的输入数量，范围 1–4096。输出与消耗数量相同；猪灵台不足一个批量时仍按一批收取一次配置的金粒成本。
- `items`：至少两个物品 ID。组内任一物品都可转换成同组任一其他物品，不会转换成输入自身。物品 ID 重复会导致配置报错。
- `enabled`：可选，默认为 `true`；设为 `false` 可停用该条目。

避免让同一物品或互转关系重复出现在多个组里。配置允许不同组之间重叠；执行时会按 JSON 顺序采用第一个匹配的组。

猪灵台从组内其他物品中随机选择产物，玩家不能指定目标。末地和幽匿台让玩家选择目标。

### 进阶配方

每个 `advanced[]` 条目只在幽匿台使用。示例：

```json
{
  "id": "ADV-001",
  "name": "示例配方",
  "input": "minecraft:prismarine_shard",
  "input_n": 4,
  "catalyst": "minecraft:nautilus_shell",
  "catalyst_n": 1,
  "output": "minecraft:oak_sapling",
  "output_n": 1,
  "outputs": ["minecraft:oak_sapling", "minecraft:birch_sapling", "minecraft:spruce_sapling"],
  "deaths": 8,
  "auto": true,
  "unlock": "仅作图鉴说明",
  "enabled": true,
  "returns": []
}
```

- `id`、`name`、`input`、`input_n`、`output`、`output_n`、`deaths`、`auto`：必填。数量范围为 1–4096；`deaths` 是单次操作消耗的可用灵魂数。该旧字段名为兼容现有配方保留，游戏界面显示为“可用灵魂”。
- `outputs`：可选的 2–128 项随机产物 ID 列表。运行时从列表中等概率选一个；`output`/`output_n` 保留为主产物展示字段，且 `output` 必须包含在列表里。没有 `outputs` 时只产出 `output`。
- `catalyst` / `catalyst_n`：可选的一组成对字段。需要催化物时两者都填；催化物在台内催化槽消耗。
- `returns`：可选，最多含一个 `{ "item": "物品ID", "count": 数量 }` 条目，成功后放进幽匿台返还槽。
- `auto`：为 `false` 时只能在投入槽模式下手动点击转换；连续处理、连接容器和潜影盒模式都不会执行该配方。
- `unlock`：可选说明文字，只在 JEI/REI 配方说明中展示，不会检查玩家进度或锁住配方。
- `enabled`：可选，默认为 `true`。

进阶转换按配方规定的输入、催化物、产物和返还物数量执行，不拆成较小批次。若物品槽、可用灵魂、催化物、返还槽或输出容器容量不足，则本次不会扣除任何材料或资源。带有非空容器内容、方块实体数据或实体数据的输入/催化物会被拒绝，避免丢失其内容。

## 可调整的运行设置

以下字段位于 `settings` 下的对应分区：

| 字段 | 用途与范围 |
| --- | --- |
| `piglin.cost` | 猪灵台成本物品 ID；默认 `minecraft:gold_nugget`。 |
| `piglin.cost_n` | 每批消耗数量，1–64；只在转换成功时扣除。 |
| `end.fuel` | 末地台的相位燃料物品 ID；默认 `minecraft:chorus_fruit`。 |
| `end.fuel_charge` | 每个燃料物品补充的相位，1–4096。 |
| `end.charge_per_batch` | 普通末地转换每批消耗相位，1–4096；幽匿普通转换固定为 0 相位。 |
| `sculk.ordinary_souls_per_batch` | 每次成功的幽匿普通转换按批消耗的可用灵魂数，1–4096；默认 3。旧配置缺少此字段时按 1 读取。 |
| `sculk.advanced_charge_per_operation` | 保留的兼容字段，允许 0–4096；幽匿普通和进阶转换都不消耗相位，旧配置里的非零值会被忽略。 |
| `sculk.advanced_cost` | 必须保留为兼容值 `death_count`；幽匿进阶转换实际消耗 `advanced[].deaths` 指定数量的可用灵魂，不消耗玩家经验。 |
| `sculk.consume_player_xp` | 必须为 `false`。 |
| `sculk.death_count_per_mob` | 旧兼容字段，保留并校验为 1–4096；运行时忽略该值。可用灵魂按合格生物的经验奖励乘以代码固定倍率 32 计算（1 点经验 = 32 个灵魂），该倍率不是 JSON 配置项。 |
| `sculk.death_count_capacity` | 每台幽匿台的计数上限，1–4096；默认 4096。 |
| `sculk.requires_player_kill` | 必须保留为布尔值；`true` 时仅统计由玩家造成的合格生物死亡，默认 `false`。 |

只有末地转换台使用紫颂果相位。相位不足时，末地台按 `fuel_charge` 计算要消耗的燃料数量；只有产物完成时才扣燃料和相位。幽匿普通转换每批消耗 `ordinary_souls_per_batch` 个可用灵魂，进阶转换按 `deaths` 消耗可用灵魂，两者都不消耗相位。JSON 字段 `advanced[].deaths` 和兼容值 `advanced_cost = "death_count"` 保留原名；存档的 NBT 键是 `Deaths`。界面把该资源显示为“可用灵魂”。升级旧世界时幽匿台燃料槽中的旧相位燃料会掉落返还。

转换时长由模组代码固定，并非 JSON 可调字段：黑金转换台每批 4 秒，末地转换台 2 秒，幽匿转换台 1 秒。界面显示进度动画。材料和费用在产物交付时扣除；若输出堵塞，进度仍会完成并停留，等输出空间可用后再交付产物。开启“连续”后，只要输入材料和费用足够就会自动开始后续操作；连接输入容器也会触发，无需逐批点击。`auto = false` 的进阶配方仍只能从投入槽手动执行。

连接容器由连接棒明确指定，不会自动扫描。每个端点距转换台最多曼哈顿距离 16，每台输入与输出连接共最多 8 个；一个容器不能同时承担两个角色。点击容器的面决定其漏斗侧面访问规则，双箱算一个容器；上锁容器和带未生成战利品表的容器不能连接。幽匿网络仍最多曼哈顿距离 16、最多 1024 个节点，并且只检查已加载区块。这些上限不由配置修改。

## 玩家操作要点

- 三种转换台都支持用连接棒绑定输入/输出容器。黑金没有目标选择器，输入容器材料仍按组随机转成不同物品；末地和幽匿可选择目标。只有末地/幽匿支持潜影盒内容模式。末地和幽匿可切换精确匹配或组内匹配：连接输入的“精确”匹配以投入槽样本为准且样本不消耗；潜影盒精确模式会在第一次成功后锁定输入物品种类，直到更改目标、模式或匹配方式。只处理潜影盒自身的 27 格内容，不会递归处理盒中盒。清空全部输入链接会自动回到投入槽模式。
- 连接棒由一根木棍无序合成。分别左键配对输入、右键配对输出，先点台或先点容器均可；输入显示绿色，输出显示橙色。重复同角色连接可移除，潜行点击台子清空该角色。触媒基座只支持输出连接。
- 漏斗可从上方输入槽投入材料；侧面可投入配置的燃料。幽匿台的侧面入口会接收物品到催化槽，但只有与当前进阶配方匹配的催化物才能执行转换；无效物品会留在槽内。底部可取转换产物，幽匿台还可取返还物。连接容器时遵循建立链接时点击的那一面所允许的槽位与方向。幽匿台在界面开启连续后，只要可用灵魂、主材和所需催化物足够就会自动处理可连续配方；若产物输出堵塞，完成进度会保留到可以交付时，届时才扣除材料与灵魂。`auto = false` 的配方例外。催化物和返还物分别使用独立槽位。
- 触媒基座顶部可放入一个有效触媒（槽 0）和一个源本（槽 10），源本必须是所选目标物品的普通样本，两者不消耗。侧面和底部只可取走九个产物槽（1–9）；增殖产物会送入连接棒指定的输出容器，没有绑定容器时留在产物槽。追加源本槽保留旧输出索引，旧台缺少源本时暂停，补齐后需手动开启。
- 幽匿充能来自服务器记录的真实 `Mob` 死亡事件。生物必须正踩在与台连通、上方无碰撞遮挡的幽匿方块顶面。充能按生物本来的经验奖励乘以固定 32 倍计算，并尊重 `shouldDropExperience`；不会掉经验的生物（包括本来不掉经验的幼年动物）提供 0 个灵魂。默认不要求玩家击杀，`requires_player_kill = true` 时只计入玩家造成的合格死亡。`death_count_per_mob` 继续保留并校验，但运行时不再按每只生物固定加值。每台可用灵魂上限仍为 4096。死亡奖励复用死亡过程中原版首次计算并缓存的经验值（含装备、附魔、攻击者因素和随机奖励），避免重复计算时重掷随机奖励；自然死亡路径若原版未计算，则按同一原版经验奖励接口补算一次。支持的网络节点包括幽匿方块、幽匿脉络、幽匿催发体、幽匿感测体、校频幽匿感测体和幽匿尖啸体。共享网络只把计数记给网络路径最近的一台；距离相同按 X、Y、Z 坐标顺序决定。原版经验球和掉落物不拦截；幽匿催发体照常使用死亡经验并蔓延幽匿，魂量仍按其死亡经验奖励换算。

## 非运行字段与校验

JSON 中其他字段（例如 `source_plan`、`cat`、`settings.*.mode`、容器范围副本、`settings.sculk.network` / `counting`、`settings.rules` 或额外的 `settings.ui`）是规划/标签元数据，不会配置扫描器、转换规则或界面行为。当前运行范围和规则以代码为准。

缺失的合法物品 ID 会写入同目录的 `unavailable-items.txt` 并从运行目录排除：普通组少于两个可用物品时整组不启用；进阶配方缺少任一必需物品时整条不启用。修复后重启重新读取。非法/重复 ID 或物品、缺失或格式错误的必填字段、超出范围的数值或超限目录会报配置错误并保留原文件；未知附加字段会被忽略。

上限包括：配置文件 750 KB、解析文本 250,000 字符、普通组 256 条、进阶配方 1024 条、每组 128 个物品、展开后的查看器条目 50,000 条。`groups[].items` 是至少两个且最多 128 个物品 ID 字符串的数组；启用的进阶配方的输入/每个随机产物组合不能与其他启用配方重复。整数约束适用于批量、物品数量和成本字段：`batch` 为 1–4096，`cost_n` 为 1–64，末地燃料/相位、幽匿灵魂设置及进阶配方数量为 1–4096；`sculk.advanced_charge_per_operation` 兼容范围为 0–4096。所有物品字段本身都是 ID 字符串。

## JEI、REI 与晶脉配方

JEI 和 REI 是可选查看器，均提供猪灵、末地、幽匿普通、幽匿进阶四类转换条目，并支持物品配方/用途查询、转换台分类入口及服务器目录同步。猪灵条目轮播显示该输入的随机候选产物；幽匿候选池列出全部可能结果。JEI 还提供母岩增殖台与触媒基座的触媒增殖配方；REI 当前仍只显示四类转换条目。查看器不提供自动填充或自动搬运，且都不是模组依赖。

晶脉配方单独打包在模组资源 `data/convert_table/growth_recipes.json`；它不是转换配置的一部分，也没有运行目录配置入口。服务端加载后向客户端同步，客户端菜单和 JEI 都使用服务器目录；断开连接恢复本地目录。v0.3.0 默认有 105 条配方、19 种触媒，目录版本为 2，每条包含 `id/catalyst/source/output/cost`，`source` 必须等于 `output`。每次产出一件，费用单位为生长因子；触媒与一件源本不消耗。仅接受物品基础形态，拒绝改名、附魔等组件数据。木材使用对应树苗或红树胎生苗；其他目标使用自然材料、紫水晶碎片、回响碎片、海洋之心、末影珍珠等。避免工具、船和加工物作为触媒，保留浮冰和滴水石块例外。修改源需重新构建/安装。

晶脉没有固定距离、节点、母岩、增殖台数量或总产速上限，只遍历已加载区块，不主动加载。同网多台共用预算，物理晶芽每 20 tick 只能贡献一次；有效运行基座尽量平分，缺源本、暂停或堵塞者不占份额。连通缓存随拓扑/区块变更定向失效，晶芽与矿物增量刷新，不每 tick 全量扫描或按预算逐单位循环。

生长因子以 1/1000 为微因子：普通未成熟晶芽的抽取上限为 1/1000 因子/秒，每块方解石额外增加 1/1000 因子/秒；小/中/大/成熟晶芽的自然内涵量为 16/1000、8/1000、4/1000、1/1000；成熟晶簇抽取为 0，每块平滑玄武岩只给未成熟晶芽增加 1/1000 内涵量，不增加抽取上限。矿物贴母岩仅作用于该母岩，贴连通紫水晶导体作用于整网，增益按不同方块叠加。内部使用 1/8000 的存储精度及每因子 160000 个 tick 单位，精确保留旧 1/64 及新 1/1000 进度，菜单以长整数拆为无符号短整数同步。生长减速沿用实际抽取算法（最低 15%），不按玄武岩数量乘 0.99；界面显示平均、最低、最高及分阶段相对原版的生长速度。改触媒、源本或目标清空进度，暂停保留进度，旧存档分数按旧精度迁移。

## 塑形材料、种子与钓鱼

全部刷怪蛋塑形为手动，友善生物不依赖自身专有掉落。分类材料在 `CraftMaterials` 注册，名称及一行原文在语言文件：Boughbound Reverie（自然）、Stillwater Palimpsest（水生）、Unbroken Cognizance（村民/商人）、The Unwrought Facet（异质/构造）。完整备用词库在 `规划/雪山主题备用词库.md`。相对 v0.2.0，刷怪蛋塑形 `deaths` 四倍，普通及其他进阶物品转换三倍，物品鱼转鱼桶费用为 24；导出不再次乘倍率。

普通作物池与远古作物池分别为 `SEED-VANILLA-CROPS` 和 `SEED-ANCIENT-CROPS`，六种普通作物等概率、两种远古作物等概率。后者需要 Boughbound Reverie 且不能自动；农夫乐事种子池仍依赖该模组。

钓鱼唯一源是 `data/convert_table/fishing_materials.json`，由 Fabric loot 修改事件加入内置鱼类/宝藏表的现有第一池，保留原版与其他模组条目，不给每次收获另加一次抽取；非内置数据包覆盖表不修改。鱼类新增四种材料权重 8/6/2/4，总权重由 100 变 120；宝藏新增紫水晶碎片权重 1、数量 1–3，原版六项保留，总权重 7。无海洋眷顾、开放水域且无其他改表时，四种材料每次钓获概率约 5.67%/4.25%/1.42%/2.83%，碎片约 0.71%；宝藏仍遵守原版开放水域条件。Excel 总览的概率由该唯一源与基准权重生成。

## 联机版本校验

服务端在 configuration 阶段发送真实 Fabric 元数据版本，客户端回复其元数据版本。完全相等后才允许完成配置任务进入世界；缺少协议、版本不同或 15 秒超时均拒绝。校验不是运行配方配置相等检查，管理员仍可定制服务器配方。
