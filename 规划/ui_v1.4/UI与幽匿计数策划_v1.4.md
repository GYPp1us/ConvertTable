# 转换台 UI 与幽匿计数策划 v1.4

日期：2026-09-20。范围：界面与规则草案，不包含游戏代码、资源包更新或版本迁移。

依据：用户提供的《Minecraft_26.3_转换台配方策划_v1.3.xlsx》和 conversion_tables_26.3_v1.3.toml。原稿保留，新稿另存。下面注明“建议”的数值和交互是本轮补充，不是原稿已确定的规则。

## 1. 配方理解

| 设备 | 普通转换 | 费用 | 范围与自动化 |
| --- | --- | --- | --- |
| 黑金／猪灵 | 78 个开放组内随机，排除原物品；材料数量 1:1 | 每批 1 金粒 | 两输入一输出，基础漏斗 |
| 末地 | 全部 99 个普通组内指定目标 | 紫颂果 +16 相位，每批 -1 | 曼哈顿距离 ≤4，最多 8 个容器 |
| 幽匿 | 继承末地；另有 40 个定向高级配方，其中 24 个生命塑形 | 普通相位；高级额外死亡计数 | 普通可自动化；高级逐条遵守 auto 与 unlock |

普通组成员是严格的全互转集合，不能按“材质相似”跨组。楼梯、台阶、墙分开；打蜡铜和未打蜡铜分开。高级配方允许显式方向、催化物和同种珊瑚映射。

输入容器的批量处理和“转换容器物品的外壳”不同。潜影盒等外壳改色保留内容；展开盒内转换必须主动进入对应模式。

本轮以用户提供的 26.3 白名单为策划依据，不把文件中新增物品或技术备注当作已核验的运行时注册表。当前工程仍为 26.2，实际迁移与 ID 核对留到实装阶段。

## 2. 统一视觉与布局

保持原版 GUI 的凹槽、方按钮和清晰像素轮廓。槽位基准 18 GUI px，图标 16 px；最近邻整数缩放。中文用游戏字体回退保证可读，不能把概念图里的文字直接裁成运行时按钮。

主体使用低噪点灰色面板。三款只在边框、页签和选中状态上带出材质：
- 猪灵：黑石边框、浅金四角、黑色猪鼻小徽记。
- 末地：末地石边、紫珀页签、低饱和紫色选框。
- 幽匿：深板岩边、少量骨白转角、青色选框。

槽位、目标图标和地图有不同语义：实物槽使用凹槽；目标使用虚线框与“目标预览”；地图使用格线与图例。错误同时给文字和符号，不只变色。

建议猪灵面板 176×184 GUI px；末地／幽匿主面板约 256×236，右侧目标或范围抽屉约 128 px。窄屏时抽屉替换主工作区，保留返回与当前任务条，不强行缩小文本。最终尺寸以 Minecraft GUI 比例预览为准。

## 3. 猪灵转换台

主流程仅三个实物槽：材料 + 金粒 → 产物。材料槽接受该设备开放组成员，费用槽仅接收金粒。

物品入槽后显示组名、此次件数、每批费用。“可能产物”只做说明页，不提供点击设为目标的交互。转换前的产物槽不展示一个可被误认为确定结果的幽灵目标；生图所示桦木是已完成状态。

按钮：转换一批／连续处理，另有配方说明。连续处理建议默认关闭。每批从排除输入本体后的同组候选中抽一个目标，整批得到同一种结果；建议各候选等概率。

未提交前不扣材料与金粒。任务开始后锁定抽取结果，输出满则等待，不因关窗、暂停或重开随机重抽。成功产出才统一结算。

单批上限取该组 batch；投入不足一批也可处理并消耗 1 金粒。实际数量还受输入实物数量、物品最大堆叠与输出空间限制，不允许把 16 个不可堆叠物品塞进一个输出格。

状态文案：放入材料／需要金粒／此组需末地转换台／产物槽已满／转换中／完成。

## 4. 末地转换台

主工作区从上至下：
1. 输入模式：投入槽、邻接容器、容器物品。
2. 输入与输出：实物槽，或明确标注角色的容器摘要。
3. 转换关系：源物品 → 目标预览，以及输入匹配规则。
4. 燃料槽和相位余量。
5. 本批进度、任务已完成批数和按钮。
6. 玩家背包。

右侧为目标抽屉。列表只显示当前输入可达的同组目标，可按名称／物品 ID 搜索，支持收藏与最近使用。先有输入时自动定位组；先选目标时提示可接受的输入组，不自动取走背包里的材料。

燃料与进度分开：
- 相位余量：本例 8 / 16，指当前这份已充入燃料剩余的转换次数。
- 燃料槽内未使用的紫颂果另显示堆叠数。建议仅在相位耗尽且准备执行下一批时消耗一个果实，空闲不流失。
- 队列：已完成 3 / 8 批，192 / 512 个。本批箭头另表达当前处理进度。
- 原稿没有速度数值，不虚构剩余秒数；速度确定后可增加时间提示。

容器管理抽屉显示：容器图标、名称、相对方位／距离、容量、角色。角色为输入、输出、忽略；同一容器建议不同时承担输入与输出，防止循环。最多 8 个是输入与输出的合计。双箱按一个逻辑库存显示，但必须说明两半是否都可用；最终寻址规则需在实装时明确。

先选目标 → 指定输入匹配 → 指定输出去向 → 查看预计件数与费用 → 开始。输出容器断开、卸载或已满时暂停，并指出具体容器，不偷偷改投其他位置。

## 5. 输入模式与目标匹配

| 输入模式 | 玩家交互 | 执行边界 |
| --- | --- | --- |
| 投入槽 | 把物品放入台内 | 只读台内槽，不扫描背包 |
| 邻接容器 | 在管理页指定输入与输出容器 | 只处理指定输入库存中匹配的物品 |
| 容器物品 | 把潜影盒等可承载内容的物品放入承载槽，明确选择“处理内容” | 改写盒内匹配物品，原槽回写并整体提交；盒子保留 |

承载槽和普通材料槽不能复用隐式规则：在“投入槽”里放白色潜影盒，目标是外壳改色；在“容器物品”里放同一个盒子，目标是盒内物品。进入后固定显示“当前处理：容器内容”。

普通转换提供两种匹配：
- 仅指定输入（默认）：指定物品 ID；其可保留的名称、内容等组件可不同，逐件保留。
- 同组兼容：把当前目标所在组内的其他成员转换为该目标。已经是目标的物品直接跳过，不收费。

混装容器预览按来源列出“匹配 320 / 已是目标 64 / 不匹配 192”，不匹配留在原位。切换目标或模式要先重算预览，运行中需要暂停才可改配置。建议默认只处理开始时已扫描的有限队列；持续模式另行开启，并显示运行总数，而非虚假的百分比。

若不同源物品的组件不能合并，保持分栈。批次上限 16 不等于物品能堆叠 16。盒内处理需要回写空间，空间不足时整批等待，不能丢掉溢出的产物。

高级配方的匹配按 recipe.input、catalyst、output 和门槛执行，不能借“同组兼容”放宽成任意跨类转换。珊瑚映射显示具体输入品种 → 相同品种的恢复结果，而非展示一个含糊的“任意活珊瑚”。

## 6. 幽匿转换台界面

沿用末地的输入模式、容器管理和目标抽屉，再增加：
- 顶部切换“精准转换／高级配方”。
- 高级选择页按类别浏览，显示所需材料、催化物、死亡费用和门槛；锁定配方仍可查看原因。
- 所选配方不是只选输出 ID。同一个输出若有不同配方，需同时选择具体来源，避免费用与副产物混淆。
- 催化槽只在配方需要时启用；水桶返还等信息直接显示在预览里。
- auto=false 的配方只允许台内手动执行一次，连续处理与容器模式禁用并解释原因。
- 死亡计数状态条显示“可用 48 / 本次 32 / 完成后 16”，不能用玩家等级或经验条代替。
- 右侧在“目标选择／连接范围”间切换，避免同时堆三栏。小地图入口和连接摘要常驻。

原稿写“高级额外 XP”，本稿按最小变更解释为：高级每次仍消耗 1 点相位，并额外消耗 deaths 次计数。此处属于明确化的建议解释；未改动高级配方原有材料、产物与自动化门槛。高级界面保留独立的紫色相位燃料条，与青色死亡计数分开显示。

## 7. 幽匿死亡计数规则

已确定的变更：高级配方费用从经验点改为生物在幽匿上死亡所累计的次数。旧 xp 字段改为 deaths，不吸取玩家经验，不依赖经验球数量。

以下为可评审的建议默认值，已在 v1.4 TOML 中标为 draft：
- 每个真正死亡的生物记 1 次。生物种类、经验掉落量、是否玩家击杀不改变倍率；环境致死和刷怪设施也可累计。
- 玩家、盔甲架、物品实体不计数。复活成功、不构成死亡的事件不计数；同一死亡事件只结算一次。
- 死亡瞬间的脚下支撑面必须是与本台连通的 minecraft:sculk 顶面。“在附近”或站在幽匿催发体／感测体上不能代替这个条件。
- 不取消原版经验掉落或催发体行为。这是额外的台内计数，不消耗地面方块，也不与原版经验收集争抢。
- 库存计数归该台保存，不按每个幽匿方块分散存储。满额建议 4096，超出不再新增，UI 明确显示“计数已满”。
- 从多个相连的幽匿方块触发同一次死亡仍只加 1。多台共享地面时，按网络路径距离归属最近的台；平局按坐标稳定归属，绝不每台都加。
- 台卸载时不模拟离线死亡。断开地面只影响以后的收集，不扣掉已保存计数。
- 成功转换时原子扣除材料、相位与死亡次数；输出受阻或条件失效不扣。取消未提交任务不损失资源。
- 计数持久化随方块实体保存。破坏／搬运是否保留计数需在实装时给出唯一规则；建议随掉落物保留并防复制。

费用处理：40 个配方保留原数字，暂作为死亡次数的初始草案，不宣称经验点与死亡次数具有等价经济价值。例如水桶→熔岩桶 32 次、沙→砂砾 6 次、鸡刷怪蛋 12 次、紫水晶母岩 64 次。应在玩法测试后单独调参。

## 8. 连接网络与投影

投影表达“当前实际连通且可收集的区域”，不画一圈半径光环就视作覆盖。

建议网络从台周围六个面开始搜索：幽匿、幽匿脉络、幽匿催发体、幽匿感测体、校频幽匿感测体、幽匿尖啸体可作连接节点。实心节点按面相邻；脉络只沿实际存在且连续的附着面连接，不通过其所在格的空面隔空搭桥。对角接触不连通。

建议性能边界：台中心曼哈顿距离 16 内、最多 1024 个节点，仅已加载区块。它与末地容器的距离 4 是两个不同范围，UI 不混用。达到边界或区块未加载时显示“范围不完整”，不把未知区域画成已确认断开。

范围页包含：
- 可切换层高的俯视像素网格，台位置、方位、连接的功能方块图标。
- 青色连线／描边：已连接节点；浅青面填充：有效死亡地面。
- 暗金断线：已确认存在但未连通；灰色虚线：未加载／超限未知。
- 统计“连接节点／有效地面／归本台收集地面”，共享区域另标归属。
- 点选节点可查看名称与连通路径；按钮“定位断点”高亮与当前网络接近但断开的区域。
- “显示世界投影”在场景中逐格描边，保留真实高度，不把多层投成可站立的整片平面。关闭 GUI 后可暂留，建议离开范围或再次切换时关闭。

生图里的 37 格节点、24 格有效地面是示例 UI 数据，不是范围上限。

## 9. 状态、费用与交互闭环

| 条件 | 界面反馈 | 执行行为 |
| --- | --- | --- |
| 输入与目标同一物品 | 已是目标，无需转换 | 跳过，不扣费 |
| 输入组与目标不兼容 | 此目标不接受该输入 | 禁止开始；保留原物 |
| 相位不足 | 放入紫颂果 | 等待 |
| 死亡次数不足 | 还需 N 次有效死亡；查看连接范围 | 等待；可继续积累 |
| 无有效地面 | 将幽匿地面连接到转换台 | 计数不增加；库存计数仍可用 |
| 输出满／容器断开 | 指出具体去向和原因 | 暂停；不更换去向、不扣新批资源 |
| 配方仅手动 | 该配方需手动转换 | 禁用容器与连续模式 |
| 数据保留失败 | 无法保留物品内容／组件 | 拒绝，不清空容器或文字 |
| 队列完成 | 已完成 N 个，消耗 M | 保留配置与结果 |

“暂停”不清空设置；“停止”丢弃未执行队列；“更换目标”先暂停并重算。启动前摘要显示预计件数、批次、总费用与可完成量，避免玩家把料丢进去以后才发现目标不匹配。
